# User Story `2026_048`

<!-- story-start -->As a Participant, I want an entry that arrives ahead of a gap, or before I hold its case, to be held and applied as soon as the gap is filled, so that out-of-order delivery costs no entry and no second delivery<!-- story-end -->

## Notes

Delivery order is not guaranteed, so an entry can arrive before the entry it follows, or before the case it belongs to.
Dropping it would force the CASE_MANAGER to send it again.
Holding the message as received, and draining the held entries once the chain reaches them, keeps the copy complete.
