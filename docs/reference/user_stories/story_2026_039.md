# User Story `2026_039`

<!-- story-start -->As a Participant, I want a status that another party reports to be judged against the state machines before it is recorded, accepting a forward move and refusing a backward move or an impossible state, so that a status sent in good faith is kept and an impossible one never enters the case<!-- story-end -->

## Notes

A remote party may report a move that skips steps its receiver did not see, because messages are lost or arrive late.
Refusing such a forward move would discard true information, and accepting a backward move or a state the machines forbid would record a falsehood.
The receive side therefore uses a rule that differs from the single-step rule for a node's own writes.
