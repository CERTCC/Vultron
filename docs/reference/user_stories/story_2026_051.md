# User Story `2026_051`

<!-- story-start -->As a Node Operator, I want replays and replay requests between a CASE_MANAGER and a peer that is out of step to be rate-bounded, so that a peer that stays out of sync cannot flood either node<!-- story-end -->

## Notes

A peer that keeps rejecting entries, or keeps asking for a case it cannot seed, would otherwise trigger a replay for every message.
Bounding the rate, backing off on repeats from the same position and resetting the bound when the position moves keeps recovery working while it caps the traffic.
Each limit lets the next attempt through after a bounded interval, so recovery is never blocked for good.
