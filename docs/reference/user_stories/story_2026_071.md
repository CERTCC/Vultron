# User Story `2026_071`

<!-- story-start -->As a Participant, I want the case ledger to hold only the case events that the CASE_MANAGER admitted, never a refusal, a delivery fault or the CASE_MANAGER's own working records, so that the record states what happened in the case and nothing else<!-- story-end -->

## Notes

Refusals, faults about applying entries, position statements and the records the CASE_MANAGER keeps while it works a case all stay outside the ledger.
A record that mixes case events with message handling would make every reader filter it, and two readers could filter it differently.
The verdict on an assertion is *admitted* or *refused*; Accept and Reject stay the names of activities, so a Reject that a participant sends can still be an admitted case event.
