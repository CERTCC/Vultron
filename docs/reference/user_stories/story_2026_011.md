# User Story `2026_011`

<!-- story-start -->As a Peer Implementer, I want the wire mapping of every message semantic to be specified, including the acknowledgments and error signals that change no state, so that I know which activities carry them and what receiving one obliges me to do<!-- story-end -->

## Notes

A message that changes no case state still has to travel as some activity.
Without a stated mapping, each implementation picks its own, and acknowledgments and errors stop being understood across peers.
