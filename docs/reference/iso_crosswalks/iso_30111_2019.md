# ISO/IEC 30111:2019 Crosswalk

{% include-markdown "../../includes/not_normative.md" %}

Clause 7 of [ISO/IEC 30111:2019](https://www.iso.org/standard/69725.html){:target="_blank"} **Information technology — Security techniques — Vulnerability handling processes** describes a vendor's internal handling process from receipt to post-release.
The Vultron Protocol covers the same process from the outside: the [Report Management (RM)](../../topics/process_models/rm/index.md) states a vendor passes through, the [Case State (CS)](../../topics/process_models/cs/cs_model.md) facts it establishes, and the messages it sends to tell the other participants.

The table maps each clause to the explanation page that covers it and to the section of the [Vultron Protocol Specification](../vultron-spec/index.md) that states the requirement.
Transitions are written as the state before and after, with the formal message name in parentheses.
The protocol side also names the Embargo Management (EM) state machine, each participant's [Participant Embargo Consent (PEC)](../../topics/behavior_logic/use-cases/embargo-lifecycle.md#which-messages-move-consent), and the two CS dimensions: vendor aware, fix ready, fix deployed (VFD) and public aware, exploit public, attacks observed (PXA).
