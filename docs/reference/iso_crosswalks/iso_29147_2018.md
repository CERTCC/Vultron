# ISO/IEC 29147:2018 Crosswalk

{% include-markdown "../../includes/not_normative.md" %}

[ISO/IEC 29147:2018](https://www.iso.org/standard/72311.html){:target="_blank"} **Information technology — Security techniques — Vulnerability disclosure** describes how a vendor receives reports from outside and publishes advisories.
Clauses 5 through 9 overlap with the Vultron Protocol, which gives the receiving, coordinating, and publishing steps a shared state model and a message for each step.

!!! tip "Consistent Terminology"

    Our use of the following terms is consistent with ISO/IEC 29147:2018
    _§5.4 Systems, components, and services_: Systems, Components, Products, Services, Vulnerability, and Product interdependency.

    ISO/IEC 29147:2018 _§5.5 Stakeholder Roles_ includes _User_, _Vendor_, _Reporter_, and _Coordinator_.
    We use _Deployer_ instead of _User_; the rest are consistent.
    See [CVD Roles and Participants](../glossary.md#cvd-roles-and-participants) and [§2.2 Roles](../vultron-spec/index.md#22-roles).

The table maps each clause to the explanation page that covers it and to the section of the [Vultron Protocol Specification](../vultron-spec/index.md) that states the requirement.
Transitions are written as the state before and after, with the formal message name in parentheses.
The protocol side names the Report Management (RM) and Embargo Management (EM) state machines, each participant's [Participant Embargo Consent (PEC)](../../topics/behavior_logic/use-cases/embargo-lifecycle.md#which-messages-move-consent), and the two Case State (CS) dimensions: vendor aware, fix ready, fix deployed (VFD) and public aware, exploit public, attacks observed (PXA).
