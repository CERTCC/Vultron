## Original Idea

Build a translation layer that reads a case ledger and produces the case's event
history: each Case State event (V, F, D, P, X, A) and each process-model event
(report received, validated, accepted and closed; embargo in force and ended;
participant joined and agreed to the embargo), labeled by participant and cause,
with its log index, commit stamp and claimed time.

Both proposed measures need this as input. The ordering desiderata need event
sequences; the timing metrics need event times. The ledger already holds every state
change as its own entry, but nothing turns it into an event history. The existing
scoring code in `vultron/core/case_states/hypercube.py` scores histories but has no
source of real ones. The embargo register entries and consent rows carry no
timestamps of their own, so their timing has to be joined from the ledger entries
that recorded each step.

## Plan

- A new read-only package outside the protocol path reads case-ledger JSONL, so a
  measure runs against an archived ledger, a committed demo recording, or another
  deployment's ledger. Nothing in the protocol path imports it, and it never writes.
- The JSONL walker moves out of `vultron/demo/report.py` into the shared package, so
  one walker reads the format. `vultron-demo-report` keeps its module, its per-entry
  grain, its replica-presence matrix and its demo-CI role; no `DRPT` requirement
  changes.
- Report-management, fix-path, deployment and public-state events are derived by
  comparing an entry's state against the state already reached, with the entry's
  semantic type as the cause label. A table keyed on the semantic type alone misses
  acts, because one report-management move has several wire forms.
- Embargo start, embargo exit and a participant's consent answer are derived from the
  semantic type and the carried object, because none is a status dimension and the
  register entries and consent rows carry no time of their own.
- The commit stamp and the claimed time stay separate fields and are never merged or
  substituted, because they come from different clocks.
- Four data-gap labels ride on the event record, so a measure states its limits
  instead of rediscovering the gap.
- The CASE_MANAGER's ledger copy is preferred; a merge of participant replicas is the
  fallback and reports the log indices no replica supplied.
- One case-state sequence is projected per vendor and per deployer, validated as a
  prefix. Several vendors are never collapsed into one sequence for the case; that
  question stays with #5143.
- A console script dumps one case's history as data and as a table, following the
  ledger report tool's naming and phrase-lookup conventions.
- The eleven committed canonical recordings under `ui/src/recordings/` are the test
  corpus, with a dedicated fixture for the merge path that no recording exercises.
- No ADR: the plan adds a read-only analysis package and changes no protocol
  decision, layer rule or persisted shape. ADR-0122, ADR-0124 and ADR-0079 already
  settle what it depends on.
