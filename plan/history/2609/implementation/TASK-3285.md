## Task (#3285)

Create the `docs/topics/future_work/` subsection in the Explanation nav, with a
federation design page promoted from `notes/federation_ideas.md`, an
open-questions collection page, and individual open-question include fragments.

Source: #2799. Docs PR that planned it: <https://github.com/CERTCC/Vultron/pull/3288>

## Outcome

**Completed**: 2026-09-17, in one PR with #3286.

Delivered: `index.md`, `federation.md`, `open_questions.md`, ten `_oq-*.md`
fragments, `mkdocs.yml` nav under Explanation, four new acronym registrations.

Deviations from the acceptance criteria, both deliberate:

- **Fragment naming.** AC-2 named the files `_oq_*.md` with underscores. They were
  written `_oq-*.md` with hyphens, matching the only existing precedent —
  `docs/reference/vultron-spec/_oq-*.md` and its `_open-questions.md` collection.
  One convention in the tree beats literal compliance with the AC.
- **Fragment set.** AC-2 named seven fragments, one of which was
  `_oq_directory_service`. That entry was widened into `_oq-actor-discovery`,
  covering both instance-registry discovery (from the notes file) and actor-level
  resolution (#1189), because keeping them separate would have produced two
  fragments that cross-referenced each other heavily. Three further fragments came
  from #3286.

Each fragment has two hosts — inline at its point of use in `federation.md` and
collected on `open_questions.md` — which is the pattern DF-09-008 describes and
`docs/reference/vultron-spec/` already uses.

## Content decisions made while promoting the notes file

- **Python stack notes dropped**, per AC-1.
- **ASCII sketches redrawn as Mermaid** (SG-36): a `classDiagram` for the
  Actor/Participant/Case relationship and a `sequenceDiagram` for report intake and
  case creation across two instances. The `Announce` relay JSON was kept as-is,
  since it illustrates wire shape rather than structure.
- **Authority renamed throughout.** The notes file uses "CaseActor" for the
  authority, with a header note explaining why it kept the name. Published prose
  names the authority `CASE_MANAGER` per ADR-0088 and CM-02-011, reserving
  "case actor" for the prototype identity and the provisioning service.
- **A miscitation was corrected.** The notes file attributes the
  one-actor-holds-many-cases model to CP-08-002/003. Those requirements are only
  about reading `case_actor_service_url` from config. The actual support is
  ISSUE-1872, which established that a case-actor container has one identity and
  the case travels in `activity.context`. The published page cites the model
  without repeating the wrong attribution.

## Reported, not fixed

`open_questions.md` is an assembly unit whose fragments use ten acronyms. SG-07 and
DF-09-003 want each expanded once per rendered page. Expanding ten acronyms in a
collection page's intro is prose contortion; expanding at each fragment's first use
is the per-fragment duplication ADR-0092 rejected. AS2 is expanded in the intro
(it recurs across four fragments) and the rest rely on the site-wide `abbr`
tooltips. A pure collection page is a case ADR-0092 did not consider; #3318 owns
the tooling side of this class of problem.
