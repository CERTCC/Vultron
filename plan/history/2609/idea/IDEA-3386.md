`test/ci/README-case-log-ratchet.md` opens with a scenario→harness table and
says `.github/demo-scenarios.json` "is the sole registry — the table below
mirrors it and MUST be kept in step." Nothing enforced that. The table also
carried an *In PR set* column mirroring each entry's `full_suite_only` flag,
which nothing enforced either. The table was **correct as of filing** — order,
test file paths, and all nine `full_suite_only` flags matched the registry — so
this was a hardening proposal, not a bug report.

The filed sketch was: assert the scenario sets match both directions, each row's
test file equals the registry's `test_file` and exists, and each *In PR set* tick
is present iff `full_suite_only` is falsy. Scope was estimated at one test plus
possibly a table-parsing helper shared with `test_diagnostic_map_sync.py`
(CS-22-001). Surfaced by #3337 / #3382.

**Processed**: 2026-09-21 — planning widened the scope substantially, on the
strength of three findings.

First, half the filed ACs already existed:
`test_scenario_registry_is_well_formed` and
`test_all_ci_scenarios_have_a_harness_module` already assert the registry's files
exist, are unique, and number nine. The genuinely new assertion was only
README-table ↔ registry.

Second, the scenario set is restated by hand in eight-plus places, not two — the
README, two tables in `notes/demo-ci-scenario-coverage.md`, one in
`notes/demo-ci-invariants.md`, the `demo-integration.yml` header comment,
DEMOCI-06-002/003, DEMOMA-16-002…011, `vultron/demo/scenario/README.md`,
`docs/topics/scenarios/index.md`, and the `mkdocs.yml` nav.

Third, one copy disagreed with the code: `vultron/demo/scenario/README.md`
listed a `vc` sub-command backed by `vc_demo.py` — a file that has never existed
in the repository's history and is absent from `vultron/demo/cli.py` — under a
heading reading "Available scenario demos", so a reader following the table would
run a command that does not exist. The row was not stale drift: it was added
deliberately, in the same commit as the VC scenario's spec group (DEMOMA-25), as
forward documentation of work that is specified and tracked by open issue #2591.
The defect was that a table of *available* demos could not distinguish a scenario
that exists from one that is merely intended.

The decision was therefore to remove the possibility of drift rather than detect
it: demo scenarios self-register at import time, all three per-scenario paths
derive by convention from the name rather than being stored, and every table plus
the CI matrix become derived artifacts. Two constraints shaped the design — the
`scenarios` job resolves the matrix with `jq` before any Python exists, so
`.github/demo-scenarios.json` stays committed as a generated projection; and
`notes/` and `test/ci/` sit outside the MkDocs tree, so `{% include-markdown %}`
would render literally there and only `docs/` pages can use build-time
rendering.

Implementation tracked in #3450 (build the registry and generate every committed
artifact) and #3451 (check the hand-written prose against the registry).
