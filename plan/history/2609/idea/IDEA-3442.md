## Summary

The reference implementation exposes 23 trigger endpoints —
`POST /actors/{actor_id}/trigger/{behavior}` — and `docs/` documents none of them.
The only mentions anywhere in the published tree are two incidental path strings
in `docs/reference/fv-demo-protocol.md` and one in
`docs/reference/user_stories/traceability.md`.

The endpoints, from `vultron/adapters/driving/fastapi/routers/trigger_*.py`:

```text
accept-actor-recommendation      accept-case-invite
accept-case-ownership-transfer   accept-embargo
add-object-to-case               add-report-to-case
close-report                     create-case
defer-case                       engage-case
invalidate-report                invite-actor-to-case
offer-case-ownership-transfer    offer-case-participant-role
propose-embargo                  propose-embargo-revision
reject-case-invite               reject-embargo
reject-report                    submit-report
suggest-actor-to-case            terminate-embargo
validate-report
```

A separate demo-only set lives under `/actors/{actor_id}/demo/` in
`demo_triggers.py`.

## Why this is a gap

`docs/howto/index.md` states the how-to section's audience as people "implementing
the Vultron Protocol". Trigger endpoints are the call-in surface those readers
drive — the other half of the two-surface model in
`notes/coordination-agents.md`, whose call-out half *is* documented. An
implementer wanting to make an actor propose an embargo currently has to read
`trigger_embargo.py`.

## Found via

Issue #3003, which reshaped `docs/howto/activitypub/activities/` into task guides. The
guides deliberately name trigger *behaviors* (`offer-case-participant-role`) and
not URL paths, following the precedent in `docs/howto/demos/fvv-demo.md`. That was
a decision to avoid writing 23 endpoint paths and request bodies into 13 pages
with nothing ratcheting them — see
`plan/incoming/learnings/20260918-3337-a-doc-rots-first-in-the-column-no-test-can-hold.md`.
It is not a decision that the surface should stay undocumented.

## What to decide

Which quadrant owns it, and what keeps it honest.

- A **Reference** page generated from the FastAPI schema would not rot, since the
  routers already carry `summary` and `description` for every endpoint and the app
  serves `/openapi/v2.json`. This is the option worth costing first.
- A **How-to** page per workflow would duplicate the activity guides #3003 just
  wrote, so the guides should link to the reference instead.
- Whatever lands, a ratchet asserting that every documented path exists in the
  router set (or generation from the schema, which makes the question moot) is
  what separates this from a table that is correct for one day.
