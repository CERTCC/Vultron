## Ratchet placement: pytest over pre-commit hook

AC-6 of #2552 required "a check — pre-commit hook or ratchet test — fails when
a path cited in these files does not exist." A pytest ratchet in
`test/architecture/` was chosen over a pre-commit hook for these reasons:

- Consistent with existing path/boundary checks in `test/architecture/`
- Pre-commit hooks run on staged file subsets; the ratchet needs the full
  `docs/reference/codebase/` tree visible at test time regardless of which
  files are staged
- Markdown files are excluded from the pre-commit `flake8` and `black` hooks;
  wiring a path-existence check there would require a new local hook entry

**Consequence**: a docs-only PR that only edits `docs/reference/codebase/`
files may not trigger the ratchet in CI. Tracked in #2924 (size:S) as a
follow-up to wire the test into the CI path-filter for docs-touching PRs.

## .codebase-scan.txt intentionally excluded from the ratchet

`docs/reference/codebase/CONCERNS.md` § Evidence cites
`.codebase-scan.txt` (a churn/TODO analysis generated by the
`acquire-codebase-knowledge` skill). The file is gitignored and intentionally
ephemeral — it is generated locally but never committed.

The ratchet's `_PATH_PREFIXES` does not include `.codebase-scan.txt`
(the `.c` prefix is absent), so the ratchet silently skips this citation.
**This is correct behaviour**: the ratchet should only check committed file
paths; checking gitignored generated files would cause spurious CI failures
on fresh checkouts where the file has not been regenerated.

If `.codebase-scan.txt` ever becomes a committed file, add it to `_PATH_PREFIXES`.
