## Outcome

Planned the full production CVE ID assignment behavior tree factory function,
grounded in CNA Operational Rules v4.1.0. The Phase 1 stub `create_assign_vul_id_tree`
(2-node flat Sequence) is superseded by `create_assign_cve_id_tree` (16-node tree
with a 9-child `IdAssignable` subtree).

## Key decisions

- `create_assign_vul_id_tree` → `create_assign_cve_id_tree` (rename, no backward shim)
- `AssignVulIdCallOutBundle` → `AssignCveIdCallOutBundle` with 14 factory fields
- `IsIDAssignmentAuthority` and `IsOrWillBePubliclyDisclosed` classified as
  ProtocolInternal (no factory seam); all other condition nodes are Evaluators per ADR-0024
- `AssignId` → Composer; `RequestId` → Retriever (both write ID to blackboard)
- `IdAssignable` expanded from a single Evaluator leaf to a 9-child SequenceNode
  subtree (exclusion guards cheapest-first, then positive conditions, duplicate
  check, evidence bar, holistic §4.1 judgment last)
- `IsRealVulnerability` output keys: `{is_real_vul: bool, is_real_vul_rationale: str}`
  (placeholder stubs, to be refined before issue #1558)
- No new ADR or spec group warranted (ADR-0024/ADR-0025 cover the pattern)
