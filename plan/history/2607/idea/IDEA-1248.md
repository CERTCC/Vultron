Add a `create_deploy_fix_tree` factory function in
`vultron/core/behaviors/report/` that composes the fix deployment workflow
as a production BT subtree.

The tree replaces the Phase 1 stub (PR #1357) with a full `DeployFixBT`
Fallback structure mirroring the `Deployment` tree from the legacy simulator
(`vultron/bt/report_management/_behaviors/deploy_fix.py`) with
production-layer guard and action nodes.

Tree structure:

```text
DeployFixBT (Fallback, memory=False)
├── CSinStateFixDeployed                    [early exit — fix already deployed]
├── _ShouldStayInRmDeferred (Sequence)
│   ├── RMinStateDeferred                   [check RM is DEFERRED]
│   └── CheckNoNewDeploymentInfoNode        [ProtocolInternal, reads blackboard flag]
├── _DeployFixIfReady (Sequence)
│   ├── CheckDeployerRoleNode               [reuse from case/nodes/vfd_role_guards.py]
│   ├── CheckRMStateAccepted                [new guard node]
│   ├── CheckCSFixNotYetDeployed            [new guard node]
│   ├── PrioritizeDeployment               [Evaluator call-out, factory seam]
│   ├── DeployFix                          [Evaluator call-out, factory seam]
│   ├── TransitionCStoFixDeployed          [new protocol action node]
│   └── EmitCDActivity                     [new emit node]
└── _MonitorDeploymentIfDesired (Sequence)
    ├── MonitoringRequirement              [Evaluator call-out, factory seam]
    └── MonitorDeployment                  [Actuator call-out, factory seam]
```

`DeployFixCallOutBundle` reduced from 5 fields to 4 (dropping
`deploy_mitigation_factory`): `prioritize_deployment_factory`,
`deploy_fix_factory`, `monitoring_requirement_factory`,
`monitor_deployment_factory`.

Key planning decisions:

- Full fallback scope (not Phase 1 stub) — replaces and closes concern #1813
  (Phase 1 stub missing production-layer guard nodes).
- Mitigation arm scoped out: `MitigationDeployed`, `MitigationAvailable`,
  and `DeployMitigation` belong to a distinct `create_deploy_mitigation_tree`
  (peer Idea #1826). The overarching pattern is "if fix available, deploy fix;
  else if mitigation available, deploy mitigation" — two separate trees.
- `CheckDeployerRoleNode` reused as-is from
  `vultron/core/behaviors/case/nodes/vfd_role_guards.py` (DRY).
- `CheckRMStateAccepted` guard only (no RM state transitions inside the tree)
  — deploy-fix tree should only be reachable when actor is already in RM.A.
- `CheckNoNewDeploymentInfoNode` as ProtocolInternal condition reading a
  blackboard flag written by upstream `NewDeploymentInfoSentinel` (FUZZ-08f);
  defaults SUCCESS when key absent.
- No new ADR — ADR-0025 fully covers the factory injection pattern.
- No new spec entries — BT-18 and BT-23 already cover all normative
  requirements; key name in code + docstring only.
- No new notes file — updates made to existing `notes/bt-fuzzer-rm-fix.md`.
