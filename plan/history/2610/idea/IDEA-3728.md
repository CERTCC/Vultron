## Problem

`docs-legacy-urls` (DOCBW-03-008, #3556) checks the built site against `vultron/metadata/docs/legacy_urls_baseline.txt`, a grow-only list of every page an earlier publish served. The list only stays complete if someone runs `uv run docs-legacy-urls --snapshot origin/publish` each time `publish` advances. Nothing enforces that.

If a publish adds a page that the baseline never records, and a later change moves or drops that page, the check passes and the old URL 404s. This is the same silent failure #3556 fixed.

## Idea

Enforce this where the evidence is still available: in `deploy_site.yml`, which runs on push to `publish`. Before uploading, it could fail if any `docs/**/*.md` page in the checkout is missing from the baseline. Merging to `publish` would then require the new pages to be snapshotted first, so a release can't forget. The other option is to have the workflow open a PR that adds the snapshot.

## Why it matters

Without enforcement the baseline goes stale after the first publish, and the continuity check keeps passing while covering fewer and fewer of the live URLs.

Governing specs: DOCBW-03-008, DF-09-009

**Processed**: 2026-10-20 — implementation tracked in #4966. Decision: gate only pull requests whose base is `publish` (not the deploy workflow, not an auto-opened snapshot PR); a direct push or manual deploy is an accepted gap.
