## Problem

`CaseLedgerEntry.event_type` (wire key `eventType`) holds a **semantic type**: the registry's label for the entry's AS2 payload. That is the glossary term (`CONTEXT.md`, `docs/reference/glossary.md`), which now lists "event type" as a term to avoid.
The maintainer is open to renaming the field to `semanticType` (or similar) if that is clearer to agents and readers (2026-10-15 planning session).

## Decisions needed (interactive)

1. Whether the field name is part of the hashed canonical content of an entry (`entry_hash`, `prev_log_hash`). If it is, a rename changes every stored entry's hash, and the hash chain of existing ledgers needs a plan.
2. Wire impact: the field travels in `Announce(CaseLedgerEntry)` replication and the SSE ledger stream, so peers on mixed versions would disagree.
3. Persistence impact: renaming a stored field refuses its old key via `RetiredFieldsRecord`, never an alias (`notes/datalayer-design.md`, #4128).
4. The name itself (`semanticType`, `semantics`, …), and whether the rename is worth its cost now or later.

AGENTS.md requires explicit maintainer instruction for a persistence schema change; this Idea is where that instruction is decided.
