Theme: theme:full-cvd-scenario-coverage — write branching demo scenarios as a shared prefix plus one continuation per choice.

## Problem

The scenario tree is declared on `@scenario` as an interim step. The target (maintainer direction, 2026-10-15) is **branches as composition**: a branching story is written once, as shared steps up to a named branch point, then one continuation per choice. Each registered scenario is "prefix plus choice." Ancestry then falls out of the code, and a shared prefix cannot diverge because there is only one copy.

Today sibling scenarios are full copies. For example, `fcv_demo.py` (666 lines) and `fcv_reject_demo.py` (790 lines) differ on only about 560 lines. That breaks DEMOMA-17-001 (Extract Before Reuse).

## Decisions needed (interactive; do not build without them)

1. The composition model: what a "step," a "branch point," and a "continuation" are in code, and how they fit `scenario_harness`, `ActorSession` (DEMOMA-26), and the self-registering `@scenario` decorator.
2. How a composed scenario is registered and named (letter-grammar names as a reviewed convention, DEMOCI-11-015; names are not generated from the path), and how the interim `@scenario` path declarations are retired.
3. How per-scenario spec groups (DEMOMA-09 … DEMOMA-27) and the invariant harness's required event types (DEMOMA-16) follow a composed scenario.
4. The migration order by family, for example `fcv` / `fcv-reject`, then `fvcv-*`, then `fccv-*`, then the root split between vendor-first and coordinator-first paths, and whether each family is one PR.
