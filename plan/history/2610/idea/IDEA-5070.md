## Summary

Review the draft page `docs/topics/measuring_cvd/timing_metrics.md` (PR #5067) and settle the metric catalog, the default clock, and how the data gaps are handled.

## Motivation

The page proposes margins (signed intervals for each desideratum), intervals, dwell times, spreads and counts computed from case ledger timestamps. Points that need a decision:

- Whether the CASE_MANAGER's commit stamp should be the default clock, and when the participant's claimed time is preferred.
- Which metrics matter most to a CVD program, and which are research-only.
- How to recover the first recipient's intake intervals (validate, accept), which are committed at case creation and so collapse to the creation time.
- How censored intervals (events that have not happened, such as X or A) are reported across cases.
- How the metrics relate to the service level expectation sketches in `cs_model_limitations.md` and `other_uses/policy_formalization.md`.

## Rough Approach

Review the page together with the desiderata page, since every desideratum's margin is a metric here.

**Processed**: 2026-10-29 — implementation tracked in #5476, done in the docs PR at the user's request.
Docs PR: <https://github.com/CERTCC/Vultron/pull/5475>.

Decisions: the commit stamp stays the default clock, an interval inside one participant is often better on its claimed times, a large gap between the two versions of an interval is worth reporting, and the clock is the implementer's choice; a starting set of seven metrics for a CVD program, the rest research or protocol tuning; the issue's premise that the owner's validate and accept collapse to creation was stale, since only the owner's receipt and the reporter's acceptance are seated at creation, and a bounded "report to case" research interval covers the owner's pre-case time; censoring is acknowledged (case close censors X and A for good) without prescribing a method; an SLE inherits its interval's clock.
