## Summary

Optionally add a `normative:` frontmatter key, validated and rendered by the theme, so the rule that the protocol and the reference implementation never share a nav section can be checked automatically.

## Motivation

The PR #4681 review settled that normative status is shown for now with the existing `not_normative.md` banner (described in `reference/conventions.md`), and that the separation rule is a review rule. No frontmatter key currently records whether a page is normative or which side of the divide it is on: `stakeholder_type` doesn't, since several pages declare `[platform-developer, project-contributor]`. Without one, ADR-0136's proposed DF-11 rule forbidding a nav section that holds both protocol and reference-implementation pages can't be enforced automatically.

## Rough Approach

- Decide what the key means: just `normative: true|false`, or a subject value (`protocol | implementation | neutral`) matching the review's ordered placement rule.
- Replace the hand-written `not_normative.md` includes with a banner rendered from the key.
- Add a validator that fails when a nav section mixes protocol and implementation pages.
- Pursue this only if review alone proves insufficient.
