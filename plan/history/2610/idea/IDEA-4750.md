## Summary

Decide how **threads** are implemented. A thread is an ordered reading path that starts on a reader tab's landing page and may cross tabs. *How Vultron Works* has a shared thread.

## Motivation

The PR #4681 review settled that tabs are organized by topic, with page type shown as a badge, and that topic organization alone turns into a maze. Threads give each reader a route through it: the nav is the structure, threads give the route. ADR-0136 should commit to threads in principle; this issue decides the mechanism.

## Rough Approach

Options to weigh:

- **Curated ordered lists** on each landing page (`docs/start/*.md`, plus a new *How Vultron Works* landing), checked by a generator so that listed pages exist and stay in order.
- **"Next on this path" links** on each page. These get tricky when a page sits on several threads; perhaps a thread-aware footer keyed by a query parameter or by the referring landing page.
- **A generated first draft** from `stakeholder_type` + `level`, then curated by hand. ADR-0102's rule that no page depends on a page above its level guarantees a valid order exists for each audience.

Also decide: how a page on several threads is handled, and how the agent usability test checks threads (at least one "follow your thread" task per persona).
