## Summary

Many `docs/` pages repeat the same blocks, such as openings, stated prerequisites, and orientation paragraphs, so a reader arriving by search or deep link finds each page self-sufficient. Sweep those repeats and source each one once through an `{% include-markdown %}` fragment, so every rendered page stays whole while the source holds a single copy.

## Motivation

DF-11-007 (with style-guide rule SG-44) forbids *removing* repeated openings, prerequisites and acronym expansions to make neighboring pages read as a sequence. It was added with ADR-0102, when the plan for #3512 had to settle a conflict between "readers do not read in nav order" (SG-07) and "nav order carries reading order" (`write-docs`). Its premise still holds: readers arrive from search and deep links, and the site has no analytics to say otherwise.

The rule is about the rendered page, though, and that leaves room to DRY the source. DF-10-001/002 already prefer one source with many render points, shared through include fragments. The rule's wording ("MUST NOT be removed") reads as if any de-duplication is suspect, which discourages the include approach.

Raised while planning #4750 (reading-path threads).

## Rough Approach

- Clarify DF-11-007 (and SG-44) in one sentence: the requirement is on the rendered page, so moving a repeated block into a shared fragment that each page includes satisfies it.
- Inventory repeated blocks across `docs/` and decide, per block, whether it is one authority's content (a fragment) or a page introducing itself in its own words (stays).
- Watch the page-scoped rules for fragments (DF-09-007/008, ADR-0092): acronym expansion and level checks evaluate a fragment at its hosts.
