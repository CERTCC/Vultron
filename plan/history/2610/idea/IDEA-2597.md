## Context

SR-11 added bidirectional spec-to-story traceability. During the 2026-08-25 mapping pass,
~20 protocol MUST specs covering error handling, timeout behavior, and idempotency could not
be mapped to any existing user story.

These specs describe what happens when things go wrong — malformed messages, oversized
payloads, timeouts, duplicate delivery, decryption failure. They are protocol-level
resilience contracts, not implementation details.

## Specs needing story coverage

**Inbox endpoint error responses** (`specs/inbox-endpoint.yaml`):

- `IE-02-003` — reject non-POST methods (405)
- `IE-03-001` — Content-Type validation
- `IE-03-002` — configurable max request body size
- `IE-03-003` — HTTP 413 for oversized bodies
- `IE-03-004` — document default body-size limit
- `IE-04-002` — HTTP 422 for schema validation failures
- `IE-05-001` — 100 ms response-time budget
- `IE-07-001` — consolidated response-code contract
- `IE-08-001` — structured JSON error body

**Message validation robustness** (`specs/message-validation.yaml`):

- `MV-01-005` — router returns result, never raises
- `MV-01-006` — unrecognized activity types → UNKNOWN
- `MV-03-001` — per-activity-type required-field validation
- `MV-04-001` — vocabulary membership check for object types
- `MV-09-002` — exact error type + abort-before-delivery on outbox integrity failure
- `MV-09-003` — `object_` required at construction time

**Timeout and ordering** (`specs/case-ledger-processing.yaml`):

- `CLP-06-003` — pending-assertion timeout value (default 180 s)
- `CLP-06-004` — transition timed-out assertion to timed-out state
- `CLP-06-006` — clear pending assertion on canonical confirmation

**Idempotency and retry** (`specs/case-management.yaml`):

- `CM-13-005` — embargo accept/reject handler idempotency
- `CM-13-007` — note idempotency check via `id_`
- `CM-13-008` — preserve non-null consent values on retry

**Other**:

- `OX-03-002` (`specs/outbox.yaml`) — delivery after ledger write
- `ENC-03-001` (`specs/encryption.yaml`) — decrypt before semantic extraction
- `ENC-03-002` — HTTP 400 on decryption failure

## Suggested story framing

- *As an operator running a Vultron node, I want the system to return actionable HTTP
  error codes for malformed or oversized requests, so that clients can diagnose and
  recover from protocol errors without manual inspection.*
- *As a Participant, I want message handling to be idempotent — duplicate delivery and
  retried operations should produce the same outcome — so that transient network failures
  do not corrupt case state.*
- *As a Participant, I want the system to time out unconfirmed pending assertions and
  clean them up automatically, so that case state does not accumulate stale entries.*
