# CLP-12-002 (retired)

- **Retired**: 2026-11-02 (#5358)
- **Replacement**: CLP-09-001
- **Why**: It required _CASE_AUTHORED_SIGNATURES to list every pair the CASE_MANAGER authors at case creation, but the ledger validator never reads that set, so the rule constrained nothing. Who may author an act is decided by sender entitlement at receipt (HP-01-006, HP-01-007) and by the role gate at commit (CLP-09-001); the set is deleted.
- **Last text**:

```yaml
  - id: CLP-12-002
    priority: MUST
    kind: project
    verification_debt: '#2575'
    statement: '`_CASE_AUTHORED_SIGNATURES` MUST be a complete superset of all `("verb",
      "object-type")` pairs emitted by the CASE_MANAGER during native case initialization
      (create_case, create_embargo_event, add_report_to_case, create_case_participant,
      add_participant_status_to_participant × N, add_case_status_to_case). Any pair
      present in `_CANONICAL_PAYLOAD_SIGNATURES`
      that the CASE_MANAGER natively authors MUST also appear in `_CASE_AUTHORED_SIGNATURES`.'
    rationale: >-
      The CASE_MANAGER creates each case and writes every initialization entry itself
      (ADR-0041). If its signature set misses one of those entries, the validator
      refuses the entry, and case creation needs a workaround by another actor. A
      complete set lets the CASE_MANAGER write the full initialization sequence.
    relationships:
    - rel_type: refines
      spec_id: CLP-12-001
    adr:
    - ADR-0015
    - ADR-0041
```
