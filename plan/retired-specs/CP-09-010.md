# CP-09-010 (retired)

- **Retired**: 2026-11-02 (#5470)
- **Replacement**: CP-09-004
- **Why**: CP-09-004 now requires the CASE_MANAGER's Create(VulnerabilityCase) to carry its participant records inline (ADR-0170), so this codebase's inline rule restates it.
- **Last text**:

```yaml
  - id: CP-09-010
    priority: MUST
    kind: project
    statement: >-
      This codebase MUST embed the participant objects of the CASE_MANAGER's
      `Create(VulnerabilityCase)` inline, not as bare ID strings, so that the
      report receiver's `CreateCaseReceivedUseCase` can seed its local
      participant records without a DataLayer round-trip to the CASE_MANAGER.
    rationale: >-
      CP-09-004 allows participant records inline or by reference; this item states how
      this codebase meets it (MS-12-010). This codebase fetches only the objects the
      note on AKM-05-007 lists, and a bootstrap participant is not one of them. The
      report receiver refuses a bootstrap that names a participant by bare id
      (CBT-05-009), so this codebase embeds the participants inline. This is a
      prototype choice, not a protocol rule.
    verification: Unit tests in `test/core/behaviors/case/test_case_proposal_received_tree.py` confirm `Create(VulnerabilityCase)`
      embeds participant objects inline.
    relationships:
    - rel_type: implements
      spec_id: CP-09-004
    adr:
    - ADR-0041
```
