# RSH-05-019 (retired)

- **Retired**: 2026-10-20 (#3741)
- **Replacement**: RSH-09-005
- **Why**: ADR-0107 detail 5: a received status is accepted whole or refused whole, so the ledger never records a status nobody sent (#4451 decision on #3741). The PXA acceptance rule moved unchanged into the whole-status rule.
- **Last text**:

```yaml
  - id: RSH-05-019
    priority: MUST
    kind: protocol
    statement: >-
      When adjudicating the PXA dimension of a received `Add(CaseStatus)`, the receiver MUST
      accept the asserted PXA state if and only if it is identical to the current PXA state
      or it is a monotone forward move from the current PXA state. Any other asserted PXA
      value MUST be refused and the current PXA value carried forward (RSH-05-016).
    rationale: >
      PXA state is monotone: bits only advance from unaware to aware (p→P,
      x→X, a→A) and never reverse. The received-side filter uses the weaker
      `is_monotonic_pxa_forward()` check — not the strict single-step adjacency
      `is_valid_pxa_transition()` that applies to local write nodes
      (CSB-16-002) — because a remote peer may have observed multiple PXA
      events between messages and report a combined advance that skips
      intermediate steps. Applying the strict check would refuse a valid
      multi-step advance from a peer that simply missed delivering earlier
      messages.
    verification: >
      Unit tests in `test/core/behaviors/status/test_add_case_status_bt.py`
      confirm that `FilterCsPxaDimensionNode` accepts PXA states that satisfy
      `is_monotonic_pxa_forward()` or are identical to the current PXA state,
      and refuses non-monotone-forward assertions by carrying the current value
      forward.
    note: >
      The predicate is `is_pxa_assertion_acceptable(current_pxa, asserted_pxa)`
      in `vultron/core/states/cs.py`, applied by `FilterCsPxaDimensionNode` on a
      received `Add(CaseStatus)` and by `ApplyCaseStatusFromLedgerNode` on the
      `add_case_status_to_case` ledger entry (RSH-08-004). CSB-16-002 strict
      single-step adjacency applies only to local write nodes, not to either.
    stories:
    - story_2022_045
    - story_2022_088
```
