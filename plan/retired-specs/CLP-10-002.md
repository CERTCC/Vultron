# CLP-10-002 (retired)

- **Retired**: 2026-11-02 (#5326)
- **Replacement**: CLP-09-001
- **Why**: Its pre-flight identity guard (receiving_actor_id compared with case_actor_id) no longer exists and conflicts with the role gate: CLP-09-001 makes the commit gate a role check inside the one received tree (ADR-0022, CLP-10-005), and CLP-09-004 evaluates it per invocation, so a participant's delivery commits nothing.
- **Last text**:

```yaml
  - id: CLP-10-002
    priority: MUST
    kind: project
    statement: A received-side use case MUST include a pre-flight guard that compares
      `receiving_actor_id` to `case_actor_id` before executing any canonical ledger
      commit operation; if `receiving_actor_id != case_actor_id`, the commit step
      MUST be skipped entirely
    rationale: >-
      Only the CASE_MANAGER may commit an entry. A received activity also runs at
      participants, for example as a relayed copy. Without a check before the commit, a
      participant's run would write an entry in its own store, and the chain would
      fork. The CASE_MANAGER's own delivery is the one that commits.
    verification: Unit tests for each received-side use case that participates in
      ledger authorship assert that `create_guarded_commit_case_ledger_entry_tree`
      (or the BT bridge) is NOT called when `receiving_actor_id` differs from the
      resolved `case_actor_id`.
    adr:
    - ADR-0021
```
