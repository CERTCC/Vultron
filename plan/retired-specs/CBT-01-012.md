# CBT-01-012 (retired)

- **Retired**: 2026-11-02 (#5470)
- **Replacement**: CBT-01-007
- **Why**: CBT-01-002 and CBT-01-007 now require the bootstrap case and its nested objects inline (ADR-0170), so this codebase's inline rule restates the protocol and has nothing of its own to say.
- **Last text**:

```yaml
  - id: CBT-01-012
    priority: MUST
    kind: project
    statement: This codebase MUST carry the bootstrap `VulnerabilityCase` inline in the `Create(VulnerabilityCase)`, with
      every nested domain object (e.g., each `CaseParticipant` in `case_participants`) embedded as a full inline object;
      it MUST NOT use a bare URI string for a nested object in this activity.
    rationale: >-
      This is how this codebase meets CBT-01-002 and CBT-01-007. The codebase fetches
      only the objects the note on AKM-05-007 lists, and a nested case object is not
      one of them, so a receiver here cannot read a record named only by URI. A
      bootstrap that names a participant by URI is refused (CBT-05-009). Inlining is
      a choice of this prototype, not a protocol rule: an implementation that fetches
      the reference can accept it.
    verification: Inspection of `vultron/wire/as2/vocab/` confirms that `ActivityStreamRef` fields accept bare URI strings
      without error; integration tests in `test/demo/test_case_proposal_round_trip.py` confirm that the bootstrap carries
      a fully materialized `VulnerabilityCase` and that `CaseParticipant` objects are serialized as full inline objects
      in the bootstrap payload.
    relationships:
    - rel_type: implements
      spec_id: CBT-01-002
    - rel_type: implements
      spec_id: CBT-01-007
```
