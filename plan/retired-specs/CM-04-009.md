# CM-04-009 (retired)

- **Retired**: 2026-10-08 (#4292)
- **Replacement**: MSM-07-008
- **Why**: ADR-0122 rev 2 retires the two-audience rule: an Accept(Invite(EmbargoEvent)) writes only the sender's consent row (MSM-07-003), and the case owner's Accept(EmbargoEvent, target=Case) writes the register and the owner's row together (MSM-07-008), so 'at most one per accept event' no longer describes either message.
- **Last text**:

```yaml
  - id: CM-04-009
    priority: MUST
    kind: project
    statement: >-
      A handler processing an EM state transition accept event MUST update at most one of
      CaseStatus.em_state or a participant's consent row per accept event, except when
      the accepting actor simultaneously satisfies both the case-owner and non-owner conditions
      (see CM-13-001 through CM-13-003 for the full decision logic).
    rationale: >-
      Updating both fields unconditionally would conflate the shared embargo state with a
      participant's individual consent state, corrupting the EM state machine.
    verification: Integration tests in `test/demo/` confirm that a single embargo-accept event
      updates either `CaseStatus.em_state` or a participant's consent row but never
      both unconditionally.
```
