# RSH-05-017 (retired)

- **Retired**: 2026-10-20 (#3741)
- **Replacement**: RSH-09-005
- **Why**: ADR-0107 detail 5: a received status is accepted whole or refused whole, so the ledger never records a status nobody sent (#4451 decision on #3741). Any refused CaseStatus rule refuses the whole status.
- **Last text**:

```yaml
  - id: RSH-05-017
    priority: MUST
    kind: protocol
    statement: >
      A received `CaseStatus` in which every refused dimension leaves the
      resulting snapshot indistinguishable from the case's current state MUST
      be refused in full: nothing is appended and no canonical ledger entry is
      committed.
    rationale: >
      Such an assertion carries no acceptable information. Appending it would
      grow the case's status history and the hash chain without recording any
      state change. This is the CaseStatus parallel to RSH-05-005 for
      ParticipantStatus.
    verification: >
      Unit tests confirm that a `CaseStatus` where both EM and PXA are refused
      and the result is indistinguishable from current state is rejected in full
      with no ledger entry committed.
    note: >
      Implemented by `FinalizeCsFilterNode.update()` returning `Status.FAILURE`
      when `(filtered.em.state, filtered.pxa.state) == (current.em.state,
      current.pxa.state)`.
    lint_suppress:
    - missing_story_reference
```
