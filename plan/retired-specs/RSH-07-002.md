# RSH-07-002 (retired)

- **Retired**: 2026-10-30 (#5511)
- **Why**: ADR-0166: adopting a P, X or A value also authorizes the embargo teardown it calls for, so the separate teardown authorization gate is removed.
- **Last text**:

```yaml
  - id: RSH-07-002
    priority: MUST
    kind: protocol
    statement: >
      Before it executes a teardown that an adopted P, X or A value calls for,
      the CASE_MANAGER MUST by default get the Case Owner's approval.
      RSH-03-001 says when a teardown is called for.
    rationale: >
      Belt-and-suspenders: adoption and teardown each default conservatively, so
      an adopted claim cannot end an embargo with no Case Owner confirmation.
      Every implementation holding the CASE_MANAGER role obeys this, because it
      decides what the receiver does once canonical state calls for a teardown.
      In this codebase the rule is the `EmbargoTeardownAuthorizationGate`
      (RSH-02-002). See ADR-0076 for full justification. Amended by ADR-0080 for
      the mechanism only; the conservative default is unchanged.
    verification: >
      With the default bundle, `ThreatTerminationBranchNode` does not execute until
      Case Owner authorization is recorded in the case ledger
      (`TestAdoptedThreatTeardown::test_a_refusing_teardown_gate_holds_the_embargo`).
    adr:
    - ADR-0076
    - ADR-0080
    stories:
    - story_2022_081
```
