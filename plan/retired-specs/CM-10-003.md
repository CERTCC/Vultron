# CM-10-003 (retired)

- **Retired**: 2026-11-02 (#5358)
- **Replacement**: CM-10-001
- **Why**: It repeats part of CM-10-001: the embargo_consents rows CM-10-001 already requires are the record from which a participant's invited, accepted, declined and expired embargoes are read, so a SHOULD to expose them adds no obligation (#5358).
- **Last text**:

```yaml
  - id: CM-10-003
    priority: SHOULD
    kind: project
    statement: >-
      The `CaseParticipant` model SHOULD expose the IDs of the `EmbargoEvent` objects the participant has
      invited to, accepted, declined or let expire as `embargo_consents` rows (CM-10-001, CM-18-001), from which
      the embargoes it accepted, explicitly or by containment, are read.
    rationale: >-
      A caller that asks which embargoes a participant was invited to, accepted,
      declined or let expire must have one place to read the answer. The
      `embargo_consents` rows give the same answer that the content gate reads
      (CM-10-004). A separate list of accepted IDs would be a second record of consent
      that can disagree with the rows (CM-10-001).
    adr:
    - ADR-0093
```
