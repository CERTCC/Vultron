# BTND-01-004 (retired)

- **Retired**: 2026-11-16 (#6514)
- **Replacement**: BTND-01-009
- **Why**: Reversed by #6514: a per-act value, a case id among them, reaches a node through a named blackboard key in every tree and never a constructor parameter, so a tree's shape is fixed by its act (ADR-0207).
- **Last text**:

```yaml
  - id: BTND-01-004
    priority: MUST
    kind: project
    verification_debt: '#2574'
    statement: >-
      Some values vary by usage site, and every tree that uses the node knows them at
      build time. A BT node MUST take each such value as a constructor parameter.
      Such values include an actor identity, a CVD role and a case ID. BTND-01-006
      covers the other values.
    rationale: >-
      A constructor parameter makes each such value an explicit input. The caller that
      builds the tree then decides the value, so one node class serves every actor and
      every case. A constructor cannot carry a value that does not exist when the tree
      is built, such as a case that an earlier node in the same tick creates or
      resolves from the activity.
    relationships:
    - rel_type: implements
      spec_id: BTND-01-001
    see_also:
    - spec_id: BTND-01-006
      reason: >-
        scope boundary: BTND-01-006 covers the values a tree finds only at tick time
```
