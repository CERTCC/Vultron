# CLP-03-003 (retired)

- **Retired**: 2026-10-28 (#5326)
- **Replacement**: CLP-02-013
- **Why**: ADR-0041 removed the proto-case: no case ledger exists before the CASE_MANAGER creates the case, so report receipt writes no entry. CLP-02-013 already keeps activities processed before a case exists off the ledger, and CLP-07-011 makes the Create(VulnerabilityCase) the genesis entry.
- **Last text**:

```yaml
  - id: CLP-03-003
    priority: MUST
    kind: protocol
    statement: The assertion-recording model MUST support continuity from report receipt
      through the case lifecycle so that all history — including the proto-case stage
      (RM.RECEIVED / RM.INVALID) — is captured in the case audit ledger
    rationale: >-
      The report and its first validation decide what the case becomes. If the ledger
      starts only when a case exists, the earliest decisions are not in the shared
      history, and a replica cannot show why the case started.
    verification: >-
      `test_report_receipt_is_recorded_in_the_case_ledger` in
      `test/core/use_cases/received/test_submit_report_received.py` checks for a
      `CaseLedgerEntry` after report receipt at RM.RECEIVED. It is a strict `xfail`:
      no ledger exists before the case (ADR-0041), and #5326 holds the conflict.
    stories:
    - story_2022_045
    - story_2022_074
    - story_2022_088
```
