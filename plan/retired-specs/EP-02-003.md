# EP-02-003 (retired)

- **Retired**: 2026-10 (audit of unsupervised decisions, #4195)
- **Why**: stated a stored-record model (a free-standing `EmbargoPolicy` record in the
  actor's store, found by a store-wide scan). #4027 replaced that model with the
  `embargo_policy` field of the actor profile but rewrote this ID in place, reusing
  the ID with a different obligation. The current rule is EP-02-005.
- **Last text of the stored-record model** (as of the #3995 merge):

```yaml
- id: EP-02-003
  priority: SHOULD
  kind: protocol
  statement: >-
    A hosted Actor SHOULD be able to publish or replace its embargo policy at
    `PUT /actors/{actor_id}/embargo-policy`, carrying only the terms (EP-01-002,
    EP-01-003). The record's `actor_id` and `inbox` MUST be derived from the addressed
    actor's own record, never taken from the body, and the record MUST be persisted in
    that actor's own store so that it is the actor default shortest-wins reads at case
    creation (EP-04-003, EP-04-010). A replace MUST leave exactly one policy for the actor.
  rationale: >-
    Nothing in the API wrote an `EmbargoPolicy` before #3972; the only writers were tests
    and the demo seeder, so a Receiver could not be given an actor default without reaching
    into its store. Deriving `actor_id` from the path actor keeps a body from publishing
    terms in another actor's name (EP-01-005); deleting superseded records keeps
    `owner_embargo_policies` from handing the comparison a default the actor withdrew.
```
