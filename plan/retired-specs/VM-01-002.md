# VM-01-002 (retired)

- **Retired**: 2026-11-03 (#5469)
- **Replacement**: VM-01-008
- **Why**: It names VOCABULARY as the sole type lookup, which the code no longer has: WIRE_TYPE_MAP resolves an inbound type value (VM-01-008), and VM-06-008 sets which callers may also reach the core map.
- **Last text**:

```yaml
  - id: VM-01-002
    priority: MUST
    kind: project
    statement: The `VOCABULARY` singleton MUST be the sole authoritative source for type lookup during dynamic deserialization
    rationale: >-
      If two lookups can answer the same `type` value, the same body can deserialize to
      different classes on different code paths, and a defect in one path is not seen in
      the other. One lookup gives every caller the same answer. The registry keys are
      set by VM-01-004 and VM-01-008, and VM-06-008 sets which callers may also reach
      the core map.
    verification: Unit tests in `test/wire/as2/vocab/base/test_registry.py` confirm that `find_in_vocabulary()` returns the
      correct registered class for a known type and raises `KeyError` for any unregistered type name.
```
