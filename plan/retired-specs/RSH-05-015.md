# RSH-05-015 (retired)

- **Retired**: 2026-10-20 (#3741)
- **Replacement**: RSH-09-005
- **Why**: ADR-0107 detail 5: a received status is accepted whole or refused whole, so the ledger never records a status nobody sent (#4451 decision on #3741). A received CaseStatus is accepted whole or refused whole too.
- **Last text**:

```yaml
  - id: RSH-05-015
    priority: MUST
    kind: protocol
    statement: >
      A CASE_MANAGER receiving an `Add(CaseStatus, Case)` MUST adjudicate the EM
      and PXA dimensions of the reported case status independently. An
      unacceptable value in one dimension MUST NOT cause the value reported in
      the other dimension to be discarded.
    rationale: >
      EM and PXA are independent state machines within CaseStatus (parallel to
      RM, VFD, EM, PXA in ParticipantStatus). A value that is unacceptable in
      EM carries no information about PXA and vice versa. Discarding the whole
      snapshot destroys state the receiver has no grounds to refuse. Liberal
      accept (ISSUE-2229): accept everything acceptable.
    verification: >
      Unit tests for `add_case_status_tree` confirm that an unacceptable EM
      value does not discard an accepted PXA value from the same CaseStatus
      snapshot, and vice versa.
    note: >
      Implemented by the three-node sequence `FilterCsEmDimensionNode`,
      `FilterCsPxaDimensionNode`, and `FinalizeCsFilterNode` in
      `vultron/core/behaviors/status/nodes/cs_dimension_filter.py`, wired as
      precondition guards of `add_case_status_tree`. See ISSUE-2256.
      RSH-04-005 refuses an `Add(CaseStatus)` sent to the CASE_MANAGER, so the
      receiver this requirement names goes away when #4851 implements it;
      #4851 rescopes or retires this requirement.
    lint_suppress:
    - missing_story_reference
```
