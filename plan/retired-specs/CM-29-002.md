# CM-29-002 (retired)

- **Retired**: 2026-11-03 (#5749)
- **Replacement**: CM-29-001
- **Why**: CM-29-001 now selects the current status by append order and sorts nothing, so no sort tiebreaker exists for the id_ field to be kept out of.
- **Last text**:

```yaml
  - id: CM-29-002
    priority: MUST_NOT
    kind: project
    statement: >-
      `VulnerabilityCase.current_status` MUST NOT use the `id_` field as a sort
      tiebreaker when it determines the most-recent `CaseStatus`.
    rationale: >-
      If `id_` breaks ties between statuses with equal times, the order depends on
      the id scheme. Auto-seeded statuses have `urn:uuid:` ids, which sort above
      `https://` ids, so an initial auto-seeded status would win over a received
      status with the same time. An id scheme is an implementation detail, not a
      measure of time.
    verification: >-
      `test_current_status_ignores_id_scheme_when_times_are_equal` in
      `test/wire/as2/vocab/test_vulnerability_case.py` gives a `urn:uuid:` status
      and an `https://` status the same `published`, appends the `https://` one
      last, and asserts it is current.
    relationships:
    - rel_type: extends
      spec_id: CM-29-001
```
