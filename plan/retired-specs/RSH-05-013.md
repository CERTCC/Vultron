# RSH-05-013 (retired)

- **Retired**: 2026-10-20 (#3741)
- **Why**: ADR-0107 detail 5: a received status is accepted whole or refused whole, so the ledger never records a status nobody sent (#4451 decision on #3741). The ledger_payload_object_override consumer is removed from CommitCaseLedgerEntryNode.
- **Last text**:

```yaml
  - id: RSH-05-013
    priority: MUST
    kind: protocol
    statement: >
      `CommitCaseLedgerEntryNode` MUST raise a hard failure — not a warning —
      if the `fields` dict of `ledger_payload_object_override` contains a key
      that is not a recognized wire alias for the snapshot object type.
    rationale: >
      An unrecognized alias applied to the canonical snapshot would silently add
      unexpected content to the hash-chained ledger entry, which every replica
      and the invariant harness would then apply. Data integrity requires a hard
      stop; the correct response is to fix the producer (RSH-05-012), not to log
      and continue.
    verification: Unit tests in `test/core/behaviors/case/nodes/test_lifecycle.py` confirm `CommitCaseLedgerEntryNode` raises
      a hard failure (not a warning) when `fields` contains a key not present in `_SNAKE_TWINS`.
    stories:
    - story_2022_045
```
