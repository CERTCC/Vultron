# CLP-12-001 (retired)

- **Retired**: 2026-11-02 (#5358)
- **Replacement**: CLP-09-001
- **Why**: It required the validator to accept a CASE_MANAGER-authored Add(CaseStatus) entry, through `_CASE_AUTHORED_SIGNATURES`, a set the validator never reads: the validator accepts every registered signature whoever authored it, so the rule constrained nothing. Who may author an act is decided by sender entitlement at receipt (HP-01-006, HP-01-007) and by the role gate at commit (CLP-09-001); the set is deleted.
- **Last text**:

```yaml
  - id: CLP-12-001
    priority: MUST
    kind: project
    verification_debt: '#2575'
    statement: '`Add(CaseStatus)` ledger entries authored by the CASE_MANAGER MUST be
      accepted as canonical entries by the ledger validation step.'
    rationale: >-
      The CASE_MANAGER writes an `Add(CaseStatus)` entry when it creates a case natively
      (CM-22-003). If the validator does not accept that entry, case creation fails at
      its last step, or the report receiver must write the entry, which CM-22-003
      forbids (ADR-0041).
    relationships:
    - rel_type: implements
      spec_id: CM-22-003
    adr:
    - ADR-0041
```
