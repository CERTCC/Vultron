# RSH-05-002 (retired)

- **Retired**: 2026-10-20 (#3741)
- **Replacement**: RSH-09-001
- **Why**: ADR-0107 detail 5: a received status is accepted whole or refused whole, so the ledger never records a status nobody sent (#4451 decision on #3741). Refused dimensions are no longer carried forward into a recorded status.
- **Last text**:

```yaml
  - id: RSH-05-002
    priority: MUST
    kind: protocol
    statement: >
      When a dimension is refused, the receiver MUST record the participant's
      current value for that dimension alongside the accepted values from the
      other dimensions, as a single `ParticipantStatus`.
    rationale: >
      The recorded status must remain a coherent snapshot of the receiver's
      view of the participant. Omitting the refused dimension would leave it
      undefined; recording the asserted value would adopt a claim the receiver
      just refused.
    verification: Unit tests in `test/core/behaviors/status/test_partial_accept_participant_status.py`
      confirm the refused dimension is replaced by the current value in the recorded `ParticipantStatus`.
    stories:
    - story_2022_045
    - story_2022_088
```
